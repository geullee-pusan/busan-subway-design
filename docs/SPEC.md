# 부산 도시철도 설계 게임 — 기획안 v1

> Claude Code 세션용 기획 문서다. 저장소에 `docs/SPEC.md`로 두고, 함께 받은 `CLAUDE.md`는 저장소 맨 위에 둔다.
> 작성 기준일은 2026년 9월 22일이다. 날짜가 붙은 사실(개통 예정일 등)은 개발할 때 다시 확인한다(14장).

## 1. 한눈에 보기

- **무엇을:** 부산의 실제 지형, 인구, 노선망 위에 새 도시철도 노선을 설계하고, "하루 운행"을 돌려 결과를 확인하는 태블릿용 HTML 게임.
- **누구를 위해:** 철도를 좋아하는 초등 3~4학년. 역 목록을 외우고 철도 뉴스를 챙겨 보는 아이. 읽기와 계산은 3~4학년 수준으로 가정한다.
- **핵심 경험:** 외우기에서 만들기로. 정답이 없는 설계, 예측 가능한 결과, 부모에게 설명하며 끝나는 한 판.
- **왜 부산인가:** 산이 도시를 가르고, 강과 바다가 길을 막고, 사람들은 해안과 골짜기를 따라 길게 산다. 아이가 사는 도시의 제약이 곧 게임의 규칙이 된다.

## 2. 절대 원칙 (모든 단계에서 지킨다)

### 2.1 중독 방지

| 넣지 않는 것 | 대신 이렇게 |
|---|---|
| 무작위 요소(뽑기, 랜덤 이벤트, 깜짝 보너스) | 같은 설계는 언제나 같은 결과. 시뮬레이션 코드에 `Math.random` 금지 |
| 점수, 별, 배지, 등급, 순위표 | 결과는 사실만 보여준다(이용객 수, 걸린 시간, 공사비) |
| 연속 접속 보상, 출석 체크, 안 들어오면 줄어드는 수치 | 저장하면 그대로 기다린다 |
| 알림, 푸시, 빨간 숫자 배지 | 없음 |
| 제한 시간, 카운트다운 | 한 수씩 두는 방식. 언제든 멈출 수 있다 |
| 자동으로 이어지는 다음 판 | 한 판은 하루 운행. 막차 뒤 결과표에서 끝난다 |
| 광고, 외부 링크, 결제, 사용 추적 | 없음 |

### 2.2 현실성

- 부산의 실제 공공 데이터를 쓰고, 화면의 모든 숫자에 출처를 단다(앱 안의 "이 숫자는 어디서 왔나요?" 버튼).
- 모델이 단순하게 줄인 부분은 숨기지 않는다. "우리 게임의 약속" 화면에 규칙으로 보여준다.
- 기존 노선망으로 돌린 결과가 실제 승하차 자료와 비슷해야 한다(5.6절).

### 2.3 아이 눈높이

- 한 화면에 한 가지 일만 한다.
- 문장은 짧게 쓰고, 어려운 낱말은 풀어 쓰거나 낱말 카드로 설명한다.
- 숫자는 항상 막대나 아이콘 같은 그림과 함께 보여준다.
- 아이용처럼 꾸미지 않는다. 이 아이는 진짜 노선도와 진짜 숫자를 원한다.

## 3. 플레이어 가정: 초등 3~4학년

**읽기**
- 한 문장에 한 가지 뜻만 담는다(25자 안팎).
- 말투는 "~해요"체.
- 한자어는 풀어 쓴다.

| 쓰지 않는 말 | 쓰는 말 |
|---|---|
| 수요 | 타고 싶은 사람 |
| 역세권 | 역까지 걸어서 10분 |
| 혼잡도 | 얼마나 붐비나 |

**숫자 표시 두 단계** (부모 화면에서 선택)

| 항목 | 기본 모드 (3학년 권장) | 진짜 숫자 모드 (4학년 권장) |
|---|---|---|
| 이용객 | "약 4만 2천 명" + 막대 | "42,380명" + 막대 |
| 공사비 | 벽돌 블록(1블록 = 100억 원) | "8,360억 원", "1조 1,265억 원" |
| 시간 | "2분 20초" | "2분 20초" |
| 거리 | "1km 600m" | "1km 600m" |

큰 수(만, 억, 조)는 3~4학년군에서 배우지만 배우는 학년은 교과서마다 다를 수 있다. 그래서 모드를 나눴다.

**조작**
- 버튼은 최소 48px, 글자는 18px 이상.
- 한 손가락 조작이 기본이다. 두 손가락은 확대와 축소에만 쓴다.

## 5. 부산 현실 모델

### 5.1 지도 범위와 격자

- **범위:** 부산 전역에 양산(북정)과 김해(가야대) 가장자리를 더한다. 울산 방면 동해선은 지도 밖을 가리키는 화살표로 표시한다.
- **격자:** 한 칸은 1km × 1km이고, 전체는 약 50 × 58칸이다(Phase 0에서 확정). 칸을 세면 거리가 된다.
- **지도의 요소:** 방위표(북쪽이 위), 축척 막대("5칸 = 5km"), 범례를 늘 표시한다.
- **두 가지 보기:** 실제 지도(격자)와 노선도(단순화)를 오간다. 같은 노선이 두 지도에서 어떻게 달라 보이는지가 그 자체로 배울 거리다.

### 5.2 지형과 공사

| 지형 | 부산 예시 | 공사 방식 | 공사비 계수 | 걷는 시간 계수 |
|---|---|---|---|---|
| 평지(도시) | 서면, 동래, 해운대 평지 | 지하 | 1.0 | 1.0 |
| 언덕 | 산복도로 마을 | 깊은 지하 | 1.2 | 1.5 |
| 산 | 금정산, 백양산, 황령산, 구덕산, 장산 | 터널 | 1.5 | 사람이 살지 않음 |
| 강 | 낙동강, 수영강 | 다리 | 1.3 | – |
| 바다 | 영도 앞바다, 해안 | 바다 밑 또는 해상 다리 | 3.0 | – |
| 외곽 들판 | 강서 | 고가 | 0.6 | 1.0 |

- 공사비 기준은 1km당 약 800억 원이다. 하단–녹산선이 13.47km에 1조 1,265억 원이므로 km당 약 836억 원이다.
- 모든 계수는 `config`에 두고, 출처를 `data/SOURCES.md`에 적는다.
- **노선 종류:**
  - 지하철: 기본값.
  - 고무바퀴 경전철: 공사비가 싸고 정원이 적다. 4호선, 사상–하단선, 양산선이 실제 사례다.

### 5.3 사람: 사는 곳과 가는 곳

**사는 사람**
- 행정동별 주민등록 인구를 행정동 경계에 맞춰 칸에 나눈다.
- MVP에서는 구·군 인구를 밀도 등급(도심, 주거, 외곽, 없음)에 따라 칸에 배분한다.

**가는 곳**
- 중심지 목록으로 표현한다. 각 중심지는 종류와 크기(1~5)를 가진다.

| 종류 | 부산 중심지 |
|---|---|
| 상업·교통 | 서면 |
| 교통 | 부산역, 김해공항 |
| 상업·관광 | 남포·자갈치 |
| 관광 | 해운대, 광안리 |
| 상업·전시 | 센텀시티·벡스코 |
| 행정 | 연산·시청 |
| 교통·산업 | 사상 |
| 대학 | 부산대, 경성대 |
| 산업 | 녹산, 명지 |

- 가능하면 사업체 종사자 수로 보강한다.
- 중심지 종류와 크기는 아이가 탐험 모드에서 직접 확인하고 고칠 수 있게 한다(지역의 중심지 탐구).

### 5.4 노선망 (상태별)

| 상태 | 노선 | 비고 |
|---|---|---|
| 운행 중 | 1호선 다대포해수욕장–노포, 2호선 장산–양산, 3호선 수영–대저, 4호선 미남–안평, 부산김해경전철 사상–가야대, 동해선 부전–태화강 | 동해선은 코레일, 경전철은 별도 운영사라 데이터 출처가 다르다 |
| 개통 예정 | 양산선(양산밸리라인) 노포–북정, 11.43km, 7개 역, 2026년 12월 예정 | 뉴스 카드로 쓴다 |
| 공사 중 | 사상–하단선, 6.9km, 2027년 목표, 고무바퀴 경전철(K-AGT) | 사상역이 3개 노선 환승역이 된다 |
| 계획 | 하단–녹산선(13.47km, 11개 역) 등 | 날짜는 표시하지 않고 "계획"으로만 쓴다 |

"기본 부산"의 기준 연도는 2026년(현재)과 2027년(사상–하단선 포함 예상) 중에서 고른다.

### 5.5 이동 모델 (결정론, 설명 가능)

모든 규칙은 "규칙 카드"로 아이에게 그대로 보인다. 숨은 계산은 없다.

1. **이동 만들기**
   - 각 칸의 사는 사람 수에 하루 이동 횟수를 곱해 이동을 만든다.
   - 목적지는 가는 곳 점수에 비례해 나누되, 멀수록 덜 가게 한다(중력 모델).
2. **도시철도로 걸리는 시간**
   - 합계: 역까지 걷기 + 기다리기(배차 간격의 절반) + 타고 가기 + 갈아타기(걷기 3분 + 기다리기) + 역에서 목적지까지 걷기.
   - 걷기: 시속 4km에 지형 계수를 곱한다. 언덕에서는 1.5배 걸린다.
   - 기존 노선: 실제 역 사이 이동시간과 정차시간(초 단위 데이터)을 쓴다.
   - 새 노선: 노선 종류별 평균 속도로 계산한다.
3. **버스·자동차로 걸리는 시간**
   - 직선거리 × 1.3 ÷ 속도.
   - 속도는 도심과 외곽을 나눠 `config`에 둔다.
   - 상습 정체 도로(가야대로, 수영로 등)를 지나면 더 느리게 한다.
4. **누가 도시철도를 탈까** (탑승 규칙)
   - 탑승 비율 = 0.05 + 0.035 × (버스 시간 − 도시철도 시간, 분).
   - 결과는 0에서 0.8 사이로 자른다.
   - 아이에게는 "10분 빠르면 10명 중 4명이 타요"로 보여준다.
5. **하루를 시간대로 나누기:** 실제 시간대별 승하차 자료의 평균 모양(출근과 퇴근의 봉우리)을 그대로 쓴다.
6. **붐빔**
   - 가장 붐비는 시간대의 구간 인원 ÷ (한 시간 열차 수 × 열차 정원).
   - 100%를 넘으면 사람 아이콘이 넘쳐 보인다.

**구현 조건**
- 난수, 시각에 따라 달라지는 결과, 숨은 보정은 모두 금지한다.
- 계산 규모: 사람이 사는 칸만 계산하고, 칸마다 가까운 역 3개까지만 본다.
- 태블릿에서 1초 안에 끝나야 한다.

### 5.6 현실 확인 (보정)

**방법**
- 기존 노선망(2026년 기준)으로 모델을 돌려 실제 승하차 자료와 비교한다.
- 조정 손잡이는 네 개 이하로 제한한다: 하루 이동 횟수, 거리에 따라 줄어드는 정도, 탑승 규칙 기울기, 중심지 크기 배율.
- 모든 조정값은 문서에 남기고, 앱의 "우리 게임의 약속" 화면에도 보여준다.

**목표**
- 실제 하루 총이용객과 ±15% 안.
- 역별 순위 상관(스피어만) 0.6 이상.
- 실제 상위 10개 역 중 6개 이상이 모델 상위 15위 안.

**아이 화면**
- "우리 계산 vs 진짜" 막대그래프(상위 10개 역)를 보여준다.
- 틀린 곳도 숨기지 않고 "왜 다를까요?"라고 묻는다.

**데이터 주의**
- 환승역은 호선별 게이트가 분리돼 있는지에 따라 집계 방식이 다르다.
- 연산역은 호선별로 따로 집계되고, 수영역은 2호선 쪽에 합쳐져 있다.
- 그래서 비교는 역 단위 합계로 한다.

## 6. 한 판의 흐름 (한 판 = 하루 운행)

1. **과제 고르기:** 과제 카드 한 장을 고르거나 자유 설계를 선택한다.
2. **설계**
   - 격자 위에 선을 긋고 역을 놓는다.
   - 노선 종류와 한 시간 열차 수(6, 8, 10, 12)를 고른다.
   - 공사비와 예산이 옆에 막대로 보인다. 되돌리기는 무제한이다.
3. **어림하기:** "하루에 몇 명 탈까요?" 막대를 끌어서 어림한다. 건너뛸 수 있지만 기본으로 권한다.
4. **하루 운행**
   - 첫차부터 막차까지 약 60초짜리 애니메이션이다.
   - 시계가 돌고, 열차 점이 움직이고, 역마다 사람 막대가 차오른다. 건너뛰기 버튼이 있다.
5. **결과**
   - 이용객(막대그래프), 시간대별 이용객(꺾은선그래프).
   - 가장 붐빈 구간, 빨라진 사람 수, 공사비.
   - 주민 목소리 카드.
   - 어림과 결과 비교: "내 어림 3만 명, 계산 결과 4만 2천 명, 차이 1만 2천 명".
6. **설명하기**
   - 세 문장 틀을 채운다: "나는 ___에서 ___까지 노선을 만들었어요. 왜냐하면 ___. 결과는 ___."
   - 결과 카드를 저장하거나 인쇄한다.
   - "오늘 운행 끝" 화면으로 마무리한다.

**끝나는 방식**
- 막차 뒤에는 아무것도 자동으로 시작하지 않는다. "새 하루" 버튼은 첫 화면에만 있다.
- 부모 설정 "하루 운행 횟수": 기본값은 처음 실행할 때 부모가 정한다.
- 다 쓰면 "오늘 운행은 모두 끝났어요. 내일 첫차는 05:30"을 보여준다. 보상이나 벌칙 문구는 없다.

## 9. 규칙 카드와 부모 화면

### 9.1 규칙 카드

모델의 규칙을 아이 말로 보여주고, 부모와 함께 바꿀 수 있다. 예시:
- "환승역은 공사비가 두 배예요"
- "도시철도가 10분 빠르면 10명 중 4명이 타요"
- "언덕에서는 걷는 시간이 1.5배예요"
- "열차 한 칸에 160명이 탈 수 있어요"

**운영 방식**
- 바꾼 규칙 묶음은 "우리 집 규칙"으로 이름을 붙여 저장한다.
- 결과 화면에는 어떤 규칙으로 돌렸는지 늘 표시한다.
- 아이가 새 규칙을 생각해 내면 부모가 코드로 옮긴다. `src/content/rules.json`을 고치고, 필요하면 엔진도 고친다. **이 과정 자체가 이 프로젝트의 목표 중 하나다.**

### 9.2 부모 화면 (네 자리 비밀번호)

- 숫자 표시 모드(기본, 진짜 숫자)
- 하루 운행 횟수
- 규칙 편집
- 데이터 출처 보기
- 저장 데이터 지우기

### 10.2 처리 흐름

- **폴더 구조:** `data/raw/`(받은 원본, 고치지 않음) → `scripts/`(처리) → `data/build/*.json`(게임용, 작게).
- **출처 기록:** `data/SOURCES.md`에 파일마다 출처 주소, 받은 날짜, 이용 조건을 적는다.
- **내려받기:** 공공데이터포털의 파일 데이터는 로그인 없이 받을 수 있다. 자동 내려받기가 막히면 부모가 직접 받아 `data/raw/`에 넣는다.
- **검증 스크립트**(`npm run validate`)가 확인하는 것:
  - 모든 역에 좌표가 있는가
  - 노선 연결 그래프가 끊기지 않았는가
  - 역 사이 시간의 합이 노선 전 구간 소요시간과 ±5% 안인가
  - 칸에 나눈 인구 합계가 공식 부산 인구와 맞는가

## 11. 기술 구조

- **배포물:** `dist/index.html` 파일 하나. 데이터, 스크립트, 스타일이 모두 들어 있고 오프라인에서 동작한다.
- **개발:** `src/`를 모듈로 나누고 빌드 도구로 한 파일로 합친다(예: Vite + 단일 파일 플러그인). 외부 라이브러리는 최소로 쓰고, 그래프는 SVG로 직접 그린다.
- **폴더 구조**
```
/CLAUDE.md
/docs/SPEC.md
/data/raw/        받은 원본
/data/build/      게임용 JSON
/data/SOURCES.md  출처
/scripts/         수집, 처리, 검증
/src/sim/         순수 함수: 격자, 경로, 이동, 붐빔, 공사비 (DOM 접근 금지)
/src/ui/          화면
/src/content/     missions.json, rules.json, words.json(낱말 카드)
/tests/
```
- **저장:** `localStorage`를 쓴다(try/catch 필수). 설계 저장 칸과 부모 설정을 담는다.
- **렌더링:** 격자와 노선은 SVG. 운행 애니메이션은 `requestAnimationFrame`.
- **태블릿**
  - 가로 모드가 우선이지만 세로에서도 동작해야 한다.
  - 두 손가락 확대와 한 손가락 끌기를 지원한다.
- **설치:** GitHub Pages 같은 https 주소에 올린다. PWA로 만들어 홈 화면에 추가하고 오프라인 캐시를 쓴다.
- **테스트**(`npm test`)
  - 결정론: 같은 입력을 두 번 돌리면 결과 JSON이 완전히 같아야 한다.
  - 공사비, 최단 시간 경로, 탑승 규칙.
  - 보정 목표(5.6절).
  - 성능: 1초 이내.

## 13. 아이와 함께 쓰는 법 (부모용)

- **첫 주:** 탐험 모드만 쓴다. "우리 집에서 가장 가까운 역은?", "서면까지 몇 칸이에요?"
- **그다음:** 과제 카드를 하나씩 한다. 결과 카드는 인쇄해서 붙여 둔다.
- **실제 경험과 잇기:** 양산선이 개통하면 실제로 타 보고 게임 결과와 비교한다.
- **규칙은 아이가 제안하고, 부모가 코드로 옮긴다.** 이 협업이 앱보다 중요하다.
